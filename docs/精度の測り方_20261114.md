# 精度の測り方（audit_bench.py の採点モード）

## 1. 何を測るか

`audit_bench.py --quiz` は、ログと設問（`question.txt` の6問）を渡して回答させ、正解（`answer.json`）と照らして採点する。
自動で採点できるように、回答の最後に結論を決まった形の JSON で書かせている。

### 侵害ありのログ（11点満点）

| 項目 | 正解とする条件 |
|---|---|
| 侵害ありと判定 | `compromised` が true |
| 攻撃元 IP | 完全一致 |
| アカウント | 完全一致 |
| 侵入時刻 | 正解の日本時間から ±60秒以内（ログは UNIX 時刻なので、日本時間への換算が要る） |
| 接続先 IP | 完全一致（`SOCKADDR` の16進数の解読が要る） |
| 接続先ポート | 完全一致（同上） |
| スクリプトの取得・実行 | 操作か仕掛けの一覧に、スクリプト名がある（sudo のコマンドは16進数なので解読が要る） |
| UID 0 の利用者の追加 | 一覧に、追加された利用者名がある |
| cron の仕掛け | 一覧に cron がある |
| SSH 鍵の仕掛け | 一覧に authorized_keys がある |
| 痕跡の消去 | 一覧に bash_history（または「履歴」）がある |

### 侵害なしのログ（3点満点）

| 項目 | 正解とする条件 |
|---|---|
| 侵害なしと判定 | `compromised` が false |
| 攻撃元を挙げていない | `attacker_ip` が null・空・「不明」など |
| 仕掛けを挙げていない | `persistence` が空 |

無差別な総当たり（192.0.2.x）や正規の sudo を侵害と見誤ると、ここで点を落とす。

### JSON を出力できなかった場合
回答の全文から同じ項目を探して採点する（侵害の有無は採点できないので0点）。CSV の `json_ok` が False になるので、「形式の指示に従えなかった回」として区別できる。

## 2. 問題セット

`bench/quiz_set/` に、全モデル共通の問題を置いた。

- `inc1`〜`inc5`：侵害あり。攻撃元 IP・接続先 IP とポート・アカウント名・追加される利用者名・スクリプト名がログごとに違う（`gen_audit_log.py --vary`）。
- `clean1`・`clean2`：侵害なし。

満点は 11×5 + 3×2 = 61 点（各1回のとき）。

作り直すとき：
```bash
for s in 1 2 3 4 5; do python3 gen_audit_log.py --compact --brute 6 --target-tokens 6000 --vary --seed $s --out quiz_set/inc$s; done
for s in 11 12; do python3 gen_audit_log.py --compact --target-tokens 6000 --no-incident --seed $s --out quiz_set/clean$((s-10)); done
```

## 3. 測り方

精度は同時に使う人数では変わらないので、**1人（`-np 1`）で測る**。
ログ（モデルによって 5.7k〜7.5k トークン）＋設問（約600）＋回答（最大 2,048）が入るように、**文脈は 16k にする**。8k だと回答が途中で切れ、採点が不当に低くなる（収まらないときはスクリプトが警告を出す）。

```bash
./build/bin/llama-server -hf unsloth/Qwen3.6-35B-A3B-GGUF:UD-Q4_K_M --no-mmproj -c 16384 -np 1 --rpc 172.18.1.57:50052 --host 127.0.0.1 --port 8080 --ctx-checkpoints 0 --cache-ram 0
```
```bash
python3 audit_bench.py quiz_set/*/audit.log --quiz --runs 1 --label quiz-qwen3.6
```

- 採点モードの既定は temperature 0、推論（thinking）オフ、生成上限 2,048。temperature 0 なので、同じログを何回解かせても答えはほぼ同じになる。回数は1回でよい。
- 推論ありの精度も見るなら `--think --max-tokens 4096` を付けて別のラベルで測る。gpt-oss-120b は推論を切れないモデルなので、回答が空になったら `--max-tokens` を増やす。
- 結果は `audit_bench_results.csv` に追記される（`mode`・`score`・`score_max`・`json_ok`・項目ごとの正誤が入る）。回答の全文も残るので、採点が妥当かは読んで確かめられる。

## 4. この採点の限界

- 見ているのは「結論の JSON に正しい値・名前が書かれているか」まで。説明の文章が正しいか、根拠の挙げ方が適切かは見ていない。教材として使うなら、上位のモデルの回答は人が読んで確かめる。
- 操作と仕掛けは、名前が一覧に出てくるかで判定している。関係のないものを余分に挙げても減点されない（侵害なしのログでだけ減点される）。
- 問題は1種類の侵害の筋（総当たり → sudo → 持続化）の変形で、ログも短い。別の種類の攻撃や長いログでの力は測れていない。
- 7問・61点なので、数点の差は誤差とみる。
